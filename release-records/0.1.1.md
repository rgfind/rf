# rf 0.1.1 contract classification

Status: additive, pending release verification.

## Classification

Contract version stays `0.1`. No field, flag, code or exit meaning is
removed or renamed. No default and no cursor identity changes.

Registry changes (both add):

- New warning code `GIT_SCRUB_UNAVAILABLE` (`find`, no exit).
- `PARTIAL_RESULT` adds `why` to `appears_in`. Its summary now also says
  that a matched file that could not be read for its occurrences has
  `matches` null.

Defect fixes. Each one makes rf follow a rule that contract `0.1` already
states. They are not new meanings:

- `find` history paths and scrub hashes are read NUL-delimited. A path that
  Git quotes and a scrub hash longer than 7 characters are now read
  correctly.
- With `--matches`, an unreadable matched file has `matches: null` and a
  `PARTIAL_RESULT` warning, not an empty list. The schema already allowed
  null.
- Invalid ast-grep output gives `STRUCTURAL_UNAVAILABLE` (`tool-unusable`),
  a code that already existed, not a silent zero.
- Selected-path mode reports a walk error that can hide a selected file.
  This uses the existing `PARTIAL_RESULT` and `IO_FAILURE` rules of normal
  mode. A selected-path request in which no selected file can be read now
  exits 3, as contract `0.1` states for an unreadable path; before, it
  exited 0 with the files missing.
- A declared value flag with undecodable bytes in its value gives
  `INVALID_INPUT`, not `UNKNOWN_FLAG`. The flag is declared, so
  `UNKNOWN_FLAG` was wrong. Exit 1 in both cases.

Release must stop if the final fixture or policy metadata does not support
this classification.
