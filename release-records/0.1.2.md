# rf 0.1.2 contract classification

Status: additive, pending release verification.

## Classification

Contract version stays `0.1`. No field, flag, code or exit meaning is
removed or renamed. No default changes. Cursors from an earlier rf go
stale (see `file_bytes_hex` below). One exit
change, ruled a defect fix (Dave, 2026-11-18): see the newline pattern
below.

Capabilities changes (all add):

- `limits.scrub_log`: `{"timeout_ms": 2000, "captured_output_bytes":
  1048576}`.
- `verbs.capabilities.output_schema` and `verbs.help.output_schema`. The
  `capabilities` schema types each top-level key only. The `help` schema
  declares `meta.verb` as string or null; `help` already gave null.
- The `GIT_SCRUB_UNAVAILABLE` summary now also names the time limit. Same
  code, same `appears_in`, no exit.
- Row key `file_bytes_hex` (string or null, pattern `^([0-9a-f]{2})+$`)
  in the `content`, `find` and `why` row schemas.

Behavior changes:

- `find`: the scrub `git log` stops at 2000 ms or 1 MiB of output. Past
  either one, rf gives the existing `GIT_SCRUB_UNAVAILABLE` warning, as for
  a failed log. `data` and the exit do not change; only the scrub commit in
  the `GIT_DELETED` warning text can become "unknown". Before, `find`
  could block for minutes on a large history.
- `conformance` X-07: a JSON leaf verb with no `output_schema` is a failing
  row; before, it was skipped. rf 0.1.2 declares a schema for every JSON
  leaf verb, so the report gains two passing rows (`X-07::verb=capabilities`,
  `X-07::verb=help`): release profile 264 pass, 0 fail, 28 not applicable.
- File names that are not UTF-8 (Dave, 2026-11-18): rf keys results by
  name bytes. Each row has `file_bytes_hex`: null for a UTF-8 name, else
  the exact bytes in hex. `file` stays the lossy text, so a consumer that
  reads only `file` sees the same values as before. Two names that differ
  only in bytes that are not UTF-8 are now two rows, not one.
  `--paths-stdin` takes raw bytes; a name that is not UTF-8 was refused
  before. `--paths-envelope` reads a non-null `file_bytes_hex` first. A
  value that is not hex gives the existing `INVALID_SELECTION`, exit 1, as
  other bad selection input does. Warning `details.files` keeps display
  names only.
- Cursor staleness: the row sort key now adds `file_bytes_hex`, and each
  row has one more key, so the snapshot hash changes. A cursor from 0.1.1
  gives the existing `CONFLICT`. The cursor format does not change. This
  is the documented answer to a changed snapshot, so it is additive.

Defect fixes:

- `--matches` occurrences match each line as the searcher does: without
  its `\n`, with the `\r` of a CRLF line. Before, a pattern that used the
  `\r` (`foo\r`, `foo\s`) matched the file but lost the occurrence, so a
  matched row could have `matches: []`, which says zero occurrences.
- A pattern that can match only a newline (`foo\n`, `[\n]`) gives the
  existing `BAD_PATTERN`, exit 1 (was: zero items, exit 0). In line mode
  such a pattern can never match, so exit 0 with no files was a false
  answer. rg refuses the same patterns. Classified as a defect fix, not
  breaking: no pattern that could match a line changes its result.

Release must stop if the final fixture or policy metadata does not support
this classification.
